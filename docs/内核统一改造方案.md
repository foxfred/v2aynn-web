# 内核统一改造方案（xray + mihomo → 只用 mihomo）

> 状态：**阶段一已完成并验证（2026-10-01）；阶段二/三未动。线上行为零变化。**
> 依据：兼容性验证 + 阶段一真实数据端到端验证均已通过（见文末附录）。

## 一句话

把现在交给 xray 跑的 **802 个普通节点**也交给 mihomo，两个内核合并成一个。
**技术上已验证可行**，剩下的是工程量和风险控制问题。

---

## 一、为什么值得做

| 收益 | 说明 |
|---|---|
| **代码砍掉一块** | `internal/v2ray/` 整个包（541 行 + 4 个测试文件）可以删掉，一套代码管两种节点 |
| **磁盘省约 63 MB** | 不再需要 xray（33 MB）、xray 用的 `geoip.dat`（19 MB）和 `geosite.dat`（11 MB） |
| **真正进入 Clash 生态** | 订阅、规则、策略组、测速全是 Clash 语义，可以直接挂 metacubexd 这类成熟面板 |
| **白拿一堆功能** | mihomo 自带 DNS（fake-ip / DoH）、URL-test 自动选节点、负载均衡、规则集 |
| **知识集中** | 家宽链那套（前置组、探针、限并发测速）本来就是 mihomo 的机制，一套经验管两个场景 |
| **少一个进程模型** | 现在要维护两套「启动 / 停止 / 自愈 / 故障转移」逻辑，合并后只剩一套 |

## 二、现状 vs 改造后

| | 现在 | 改造后 |
|---|---|---|
| 普通节点（trojan/vless） | **xray** 内核，生成 JSON 配置 | **mihomo** 内核，生成 Clash 配置 |
| 家宽节点（clash 订阅） | **mihomo** 内核，改写订阅原文 | **mihomo** 内核，改写订阅原文（**不变**） |
| 内核切换 | 二选一（`config.Kernel` 字段） | **永远是 mihomo**，只是加载不同配置 |
| 分流规则 | xray `routing.rules` | Clash `rules` |
| 透明代理 | xray `dokodemo-door` :12345 | mihomo `redir-port` :12345（**已实现**） |
| 节点测速 | 走 HTTP 端口 10810 | 走 HTTP 端口 10810（**不变**） |
| 分发产物 | v2aynn-web + xray + mihomo + 两套 geo | v2aynn-web + mihomo + 一套 geo |

> 注意一个**关键点**：现在两个内核抢同一组端口、同一时刻只跑一个。
> 改造后**行为完全一样** —— mihomo 同一时刻也只加载一份配置（普通节点的，或家宽订阅的）。
> 变的只是「谁来跑」，不是「跑几份」。

## 四、关键设计决策

### 1. 普通节点的配置从哪来

现在 mihomo 的做法是「拿订阅原文，只改顶层 7 个键」（`rewriteConfig`）。
普通节点没有 Clash 原文 —— 订阅给的是一串 `trojan://` / `vless://` 链接，
程序已经把它们解析成了结构化的 `config.Node`。

所以新增一个**从 Node 列表生成 Clash 配置**的能力：

```
config.Node { protocol, server, port, uuid, password, network, tls, sni, path, reqHost }
        ↓
Clash proxy { type: trojan, server, port, password, sni, network: ws, ws-opts: {...} }
```

**这块已实现为 `internal/mihomo/nodes.go` 的 `BuildNormalConfig()`**（阶段一），
真实数据 802/802 全部转换成功，盒子上真实 mihomo `-t` 通过并全部加载。

### 2. 分流规则怎么翻译

| 现在（xray） | 改造后（Clash） |
|---|---|
| `smart`：`domain: geosite:cn` → direct | `GEOSITE,cn,DIRECT` |
| `smart`：`ip: geoip:cn, geoip:private` → direct | `GEOIP,CN,DIRECT` + `GEOIP,PRIVATE,DIRECT` |
| `global`：不加 routing（默认走出站） | `MATCH,<策略组>` |
| `direct`：全流量 → direct | `MATCH,DIRECT` |

**代价**：Clash 用 `GEOSITE` 规则需要 `geosite.dat`（约 4 MB，mihomo 格式），
现在 mihomo 工作目录里没有，要补上。项目里已有 `usesGeosite()` 检测逻辑，机制是现成的。

### 3. 「普通配置」和「家宽配置」怎么共存

mihomo 同一时刻只加载一份配置 —— 这点**不变**。
只是把「谁在跑」从「xray 或 mihomo」改成「mihomo 加载普通配置 / mihomo 加载家宽配置」。

好处：`config.Kernel` 字段可以退休，用户点节点时的分派逻辑大幅简化。
风险：从家宽切回普通节点时，要确保新配置真的被加载（不能只换内存标记）。

### 4. 透明代理

xray 用 `dokodemo-door`，mihomo 用 `redir-port: 12345` —— **后者在 9-30 家宽改造时已经做好并验证过**，
`transparent.sh` 的 REDIRECT 规则不用动。

### 5. 测速

普通节点测速是「通过 HTTP 端口 10810 发一个请求量延迟」（`server.go:1120`），
**与具体内核无关**。改造后 mihomo 监听同样的端口，测速逻辑一行都不用改。

## 五、分三步走

### 阶段一：只新增能力，不改变任何行为（可独立验证）✅ **已完成**

- ✅ 新增 `BuildNormalConfig()` + 单元测试（15 项，覆盖 trojan / vless / vmess / ss × ws / grpc / tcp / h2
  + 拒收场景 + 重名 + 转义 + 黄金输出）
- ✅ 端到端：用**真实节点**（802 个，来自盒子 `config.json`）经**生产代码**生成配置，
  在盒子上起独立 mihomo 验证通过
- ✅ **线上行为零变化**（`nodes.go` 尚无调用方，普通节点仍由 xray 跑），随时可停

**阶段一实测发现的两个坑（已处理，阶段二必须记住）**

1. **订阅里 332/802 个节点是重名的**。Clash 要求节点名唯一，重名会让内核直接报解析错误。
   现在 `BuildNormalConfig` 保留原名、只给重名的加 ` #N` 后缀，并返回 `NameToID` 映射。
   ⇒ **阶段二切节点时绝不能拿 `Node.Name` 直接去内核里找，必须走 `NameToID`。**
2. **mihomo `/version` 就绪 ≠ 配置加载完毕**，必须轮询到 `/proxies` 非空再断言。

### 阶段二：切换分派（保留 xray 代码作回滚）

- `main.go` / `server.go` 改为一律走 mihomo
- xray 代码和二进制**先不删**，留着当回滚保险
- 全量验收：节点切换、测速、透明代理、智能分流、故障转移、开机自启
- 观察运行 N 天（建议 3–7 天）

### 阶段三：清理

- 稳定后删除 `internal/v2ray/`、xray 二进制、xray 的 `geoip.dat` / `geosite.dat`
- 更新 `README.md` / `AGENTS.md`
- 备份：`cp /opt/v2aynn-web/v2aynn-web /opt/v2aynn-web/v2aynn-web.bak-<时间戳>`

## 六、风险与应对

| 风险 | 严重度 | 应对 |
|---|---|---|
| **分流规则语义差异** | 中 | xray 的 `geosite:cn` 与 Clash 的 `GEOSITE,cn` 数据源不同，可能有个别域名归类不一致。验收时专门测「国内网站直连、国外走代理」 |
| **节点通过率变化** | 中 | 验证时只抽样了 12 个（6 个通）。切换前应做**全量对比**：同一批节点在 xray 与 mihomo 下的通过率 |
| **UDP 转发差异** | 低 | 透明代理场景下 UDP 走法不同，需要实测（游戏、QUIC） |
| **内存占用** | 低 | mihomo 实测 RSS ≈ 67 MB，与 xray 同量级；两者从不同时跑，峰值不变 |
| **启动变慢** | 低 | mihomo 加载 802 个节点需要几秒（配置解析本身只要 0.4 秒）。低配盒子上要留意启动窗口 |
| **首次切换失败** | 中 | 阶段二保留 xray 二进制，回滚只需换回旧二进制 |

## 七、回滚预案

**前提**：阶段二不删 xray 相关代码与二进制 —— 这是整个方案最重要的安全垫。

回滚步骤（一条命令，30 秒内完成）：

```bash
cp /opt/v2aynn-web/v2aynn-web.bak-<时间戳> /opt/v2aynn-web/v2aynn-web
systemctl restart v2aynn-web
```

配置数据（`config.json`）**结构不变**，无需回滚数据。

## 九、明确不做的事

- ❌ **不动界面结构**（用户红线）
