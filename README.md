# v2aynn-web

低资源 Linux 设备（TV 盒子 / 路由器 / 树莓派）上的代理订阅管理器。基于 Xray-core，提供 Web 管理界面 + SOCKS5 / HTTP / 透明代理。

> **🤖 本项目由 AI 编程生成**，代码、文档、部署脚本均为人机协作的 AI 编程产物。
> **   如有大佬看上项目创意，拿去自行修改就好，本项目只提供基础使用，UI布局没什么讲究，有想法的拿去自己改。

---

## ✨ 功能特点

- **多订阅聚合**：支持多个订阅源合并管理，可配置订阅代理，支持周期自动刷新或关闭
- **协议支持**：vmess / vless / trojan / ss 四种主流协议自动解析
- **三种代理入口**：SOCKS5 (默认 10808) + HTTP (默认 10810) + 透明代理 (12345)，一键启停
- **智能分流**：国内域名/IP 直连（geosite:cn / geoip:cn），海外走代理；可切换全局模式
- **节点管理**：
  - 全部并发测速（每批 5 个），逐条实时显示结果，完成自动按延迟排序
  - 测速采用 TCP+TLS 真实握手验证（3 次采样优化为首次成功即返回，速度快、不易误判）
  - 超时节点以醒目红色标注，刷新后持久保留
  - 「更新订阅」按钮手动拉取订阅刷新列表
  - 延迟列独立显示，支持按延迟升/降序排序并**持久化保存**
  - 自动去重（相同 服务器:端口:协议 只保留一个）
  - 当前连接节点高亮
  - **手动添加节点**：支持通过表单手动填入节点信息
  - **粘贴导入节点**：支持粘贴 vless/vmess/trojan/ss 链接批量导入
  - **删除节点**：每行节点附带删除按钮
  - **真实下载测速**：通过代理隧道下载 2MB 文件计算实际 Mbps，测速 URL 可在设置中自定义
- **状态栏**：显示运行状态 + 当前节点名（长名自动省略，节点名缓存不受订阅后台刷新影响）
- **纯单页 Web 界面**：内联 CSS/JS，无任何外部依赖，移动端 / 电视浏览器友好
- **配置备份与恢复**：一键导出全部配置为 JSON 文件；导入时校验合法性（非法 JSON / 空分组会被拒绝，不会破坏现有配置），恢复后自动重启代理套用新配置
- **可靠性**：
  - 断电重启自动重连（带 5 次重试）
  - xray 进程崩溃自动拉起（最多 3 次，超过则放弃，防止无限重启）
  - **自动故障转移**：当前节点连续失败后，自动按「可达优先 + 延迟升序」尝试切换其他节点（最多 3 个），可在设置中关闭
  - 测试数据（ping/sort）随配置持久化，跨重启不丢失
  - 订阅拉取失败时保留旧节点，不整表清空
  - 手动添加/导入的节点不受订阅刷新影响，不会丢失
- **低磁盘写入**：测速结果这类高频改动只标记「待落盘」，由后台每 5 秒合并写入一次，避免每测一个节点就全量写盘，延长 TF 卡 / eMMC 寿命
- **零 Go 外部依赖**：仅使用标准库，单二进制 ~5MB
- **无需 Docker**：`start.sh` 一键启动，自动安装 xray 与 geo 数据

## 🚀 快速开始

### 方式一：一键脚本（推荐）

```bash
# 1. 下载 xray + geo 数据（约 60MB，仅首次需要）
bash download-assets.sh        # 默认 arm64；amd64: bash download-assets.sh amd64

# 2. 启动
bash start.sh

# 3. 浏览器打开
#    http://<设备IP>:8000
```

### 方式二：systemd 服务（开机自启）

```ini
# /etc/systemd/system/v2aynn-web.service
[Unit]
Description=v2aynn-web proxy gateway
After=network.target

[Service]
Type=simple
Environment=DATA_DIR=/opt/v2aynn-web/data
ExecStart=/opt/v2aynn-web/v2aynn-web
Restart=always

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl enable --now v2aynn-web
```

### 方式三：本地编译

```bash
# 要求 Go 1.22+
GOOS=linux GOARCH=arm64 CGO_ENABLED=0 go build -ldflags="-s -w" -o v2aynn-web ./cmd/server/
```

## 🔌 使用说明

1. **添加订阅**：在首页「订阅」栏填入名称和订阅 URL，点击添加
2. **测速排序**：点击「全部测速」测试所有节点延迟；点击延迟列标题按延迟排序（排序结果自动保存）
3. **切换节点**：点击节点即可切换，已连接节点有蓝框高亮
4. **透明代理**：可选，将局域网设备网关指向本机即可
5. **设置**：点顶栏「设置 ⚙」，可改 SOCKS5/HTTP 端口、Web 监听地址、订阅刷新间隔、代理模式、全局订阅代理、测速 URL，以及开关「自动故障转移」
6. **备份与恢复**：设置面板内点「导出配置」下载 JSON 备份；换设备或配置改乱时点「导入配置」选回该文件即可。导入前会校验，非法文件不会破坏现有配置

> **提示**：导入配置后建议检查一下节点列表，确认新配置里的订阅源能正常拉取。

## 📝 更新记录

### 2026-09-19

本次更新围绕「低资源占用」原则，只做减少开销与提升可靠性的改动，不引入任何常驻重量级功能。

- **测速结果合并落盘**（减少磁盘写入）：测速属高频写入，原实现每测一个节点就全量写一次 config.json。现改为只标记「待落盘」（`Config.MarkDirty()`），由后台协程每 5 秒合并写一次（`Config.Flush()`）。全量测速 200 个节点时，磁盘写入次数从约 200 次降到 1 次
- **配置备份与恢复**（新增）：
  - `GET /api/backup` 导出当前配置为带时间戳的 JSON 文件（如 `v2aynn-backup-20260919-142952.json`）
  - `POST /api/restore` 导入配置，带三重校验：非法 JSON 拒绝、没有任何分组拒绝、字段缺失回落默认值
  - 恢复后若代理正在运行会自动重启以套用新配置
  - 设置面板新增「配置备份 / 恢复」区块（导出配置 / 导入配置按钮）
- **自动故障转移**（新增）：当前节点连续重启失败后，不再直接放弃，而是自动尝试切换到其他可用节点。候选节点按「已测速可达优先 → 延迟升序」排序，最多尝试 3 个。设置面板新增开关，默认开启，可显式关闭（配置项 `autoFailover`）
- **修复两个恢复功能的字段丢失缺陷**（运行时验证发现，仅编译无法暴露）：
  - `subRefresh: 0`（合法值＝禁用自动刷新）在恢复时被误判为「缺失」而回填成 300，导致用户关闭的自动刷新被悄悄打开
  - `autoFailover` 在 `Restore()` 中整体漏拷，导致导入一份「已关闭故障转移」的备份会被静默改回默认开启
  - 新增 `internal/config/restore_test.go`，用反射遍历 `Config` 全部导出字段断言拷贝完整性 —— 以后再新增字段却忘记同步 `Restore()` 时测试会立即失败
- **代码规范化**：全部 Go 源码通过 `gofmt`（修正历史遗留的结构体字段对齐），`go vet` 无告警
- **修复「订阅刷新间隔无法设为 0」**（用户反馈）：设置界面原先校验 `refresh<10`，把 0 也一并拦下，
  导致"禁用自动刷新"这个功能在界面上根本无法设置（后端一直是支持的）。现在 0 可正常设置并持久化
  - 顺带修掉同源的显示缺陷：`subRefresh||''` 会把 0 渲染成空白，用户会以为没保存成功
  - 标签改为「订阅刷新间隔(秒，0=禁用自动刷新)」，取值规则明确为 0 或 10-86400 秒
- **修复设置接口可被单个畸形请求打死服务的严重缺陷**：`apiSettings` 使用 `int(v.(float64))` 裸类型断言，
  字段类型不符即 panic；而 `w.cfg.Unlock()` 写在函数末尾，panic 后执行不到，
  **配置锁永久无法释放，整个服务（全部 API + 前端）彻底无响应，只能重启进程**
  - 实测：发一个 `{"subRefresh":"abc"}`，服务随即对所有请求超时
  - 修复：改用 `defer` 释放锁 + 全部字段走带 `ok` 判断的安全转换 + 数值范围校验；
    校验失败时整体拒绝，不会出现"改了一半"的不一致状态
  - 新增 `internal/web/settings_test.go` 覆盖死锁回归、0 值接受、范围校验、部分失败不留痕
- **让「自动去重」真正生效**：功能列表里宣传的"相同 服务器:端口:协议 只保留一个"其实一直没生效 ——
  `dedupNodes()` 函数写好了却**从未被任何地方调用**，属于长期存在的死代码。
  现已接入 `fetchOne()`，手动拉取与后台自动刷新两条路径都会去重。
  效果：订阅源自身重复、或同一订阅里不同名称指向同一服务器时，节点不再重复占用列表与测速时间。
  新增 `internal/subscription/parser_test.go` 覆盖去重逻辑（按三字段区分、保持顺序、不修改入参等）
- **修复「代理模式-直连」是空操作**：`generateConfig()` 原先只判断 `proxyMode != "global"`，
  于是 `direct` 落进与 `smart` 完全相同的分支 —— 界面选「直连」，实际仍在按
  geosite:cn / geoip:cn 分流，国外流量照旧走代理节点。现在三种模式各有独立分支：
  - `smart`：国内域名/IP 直连，其余走代理（行为不变）
  - `global`：不生成 `routing`，xray 默认全部走第一个出站（代理节点）
  - `direct`：生成一条不带匹配条件的兜底规则（`network: tcp,udp` → `direct` 出站），
    全部流量直连；只带 `network` 是为了同时覆盖 TCP 与 UDP，避免 UDP 仍走代理
  - 未知取值回落到 `smart`（与设置接口的白名单校验互为兜底，防手工改配置文件写错）
  - 顺带修正设置界面三个选项的文案，原「智能」标签写作"仅直连受阻走代理"，
    与真实的分流逻辑（按国内/国外）并不相符
  - 新增 `internal/v2ray/manager_test.go`，其中
    `TestGenerateConfigDirectDiffersFromSmart` 断言两种模式生成的 routing **不相等** ——
    只断言"direct 有 routing"挡不住这个缺陷，因为 smart 也有
- **修复「点停止后代理又自己起来」**：`Stop()` 与「进程崩溃」对 `Manager` 而言状态完全相同
  （都是 `running=false`、`cmd=nil`），watch 无法区分，于是在崩溃后那 5 秒自愈窗口内点停止，
  xray 仍会被自己拉起来，停止功能形同虚设。现增加 `stopRequested` 标记（`Stop()` 置位、
  `Start()` 清除），watch 重启前先判断它。该缺陷在修改前的代码上同样存在，非本次引入
- **修复 `watch()` 对 `m.running` 的数据竞争**：原实现在释放 `m.mu` 之后直接读 `m.running`，
  而该字段由 `Start()`/`Stop()` 在锁内并发写入 —— 无锁读 + 锁内写 = 数据竞争。
  目标平台是 ARM64（弱内存模型），不应依赖这种读法的偶然正确性。现在该字段的所有访问
  都在 `m.mu` 内，且重启判定挪到 5 秒等待之后（能观察到并发启动的窗口最大），
  避免把"用户有意重启"误记成"节点故障"进而触发不必要的自动故障转移
  - 新增 `TestWatchRestartsDeadProcess`（自愈重启链路真的能拉起进程）与
    `TestStopDoesNotTriggerRestart`（主动停止后不再被拉起）两个运行时用例
  - 另加 `TestWatchDoesNotRaceOnRunningFlag`，**只在 `go test -race` 下运行**，
    未启用竞争检测时显式跳过 —— 否则它会变成"永远通过"的测试，给出虚假安全感
